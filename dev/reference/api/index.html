Julia API

FFTL does not export its functions. They are called qualified, FFTL.fft and so on, so that the package can be loaded next to FFTW.jl. The names listed here are public.

Complex transforms

FFTL.fft — Function
fft(x, region = 1:ndims(x))

Forward DFT of x along region (all dimensions by default), unnormalised. Equal to plan_fft(x, region) * x.

source
FFTL.bfft — Function
bfft(x, region = 1:ndims(x))

Backward DFT along region, unnormalised: applying bfft to fft(x) multiplies x by the number of transformed elements.

source
FFTL.ifft — Function
ifft(x, region = 1:ndims(x))

Normalised inverse DFT along region: ifft(fft(x)) ≈ x.

source
FFTL.plan_fft — Function
plan_fft(x::AbstractArray, region = 1:ndims(x); threads = Threads.nthreads()) / plan_bfft / plan_ifft

Plans for the forward, unnormalised backward and normalised inverse DFT along the dimensions region of arrays like x. Float32 and Float64 (real or complex) use the SIMD kernels, and transforms large enough to profit run on up to threads threads. Other floating-point types (BigFloat, Double64, Float128, …) are transformed in their own precision by a generic, single-threaded path; Float16, integers and other numbers are converted to ComplexF64.

source

plan_bfft and plan_ifft are documented with plan_fft.

Real transforms

FFTL.rfft — Function
rfft(x, region = 1:ndims(x))

Forward DFT of real x, returning the half spectrum along the first dimension of region (size(x, d) ÷ 2 + 1 values there).

source
FFTL.brfft — Function
brfft(X, d, region = 1:ndims(X))

Unnormalised inverse of the half spectrum X to a real array of length d along the first dimension of region.

source
FFTL.irfft — Function
irfft(X, d, region = 1:ndims(X))

Normalised inverse of the half spectrum X to a real array of length d along the first dimension of region: irfft(rfft(x), length(x)) ≈ x.

source
FFTL.plan_rfft — Function
plan_rfft(x::AbstractArray{<:Real}, region = 1:ndims(x); threads)
plan_brfft(X::AbstractArray{<:Complex}, d, region = 1:ndims(X); threads)
plan_irfft(X::AbstractArray{<:Complex}, d, region = 1:ndims(X); threads)

Real-input forward DFT (half spectrum along the first dimension of region), its unnormalised inverse to real arrays with length d along that dimension, and the normalised inverse.

source

plan_brfft and plan_irfft are documented with plan_rfft.

Real-to-real transforms

FFTL.dct — Function
dct(x, region = 1:ndims(x)), idct(x, region = 1:ndims(x))

Orthonormal DCT-II and its inverse (DCT-III) along region.

source
FFTL.plan_r2r — Function
plan_r2r(x::AbstractArray{<:Real}, kinds, region = 1:ndims(x); threads)
r2r(x, kinds, region = 1:ndims(x))

Unnormalised real-to-real transforms; kinds is one R2RKind (REDFT00 … RODFT11, DHT, R2HC, HC2R) for all dimensions of region or one per dimension.

source
FFTL.R2RKind — Type
R2RKind

The real-to-real kinds: REDFT00 … REDFT11 (DCT-I … DCT-IV), RODFT00 … RODFT11 (DST-I … DST-IV), DHT (Hartley), R2HC and HC2R (halfcomplex). The formulas are in the documentation (Cosine, sine and Hartley transforms).

source

idct is documented with dct, and r2r with plan_r2r.

The kinds, as constants: REDFT00 (DCT-I), REDFT10 (DCT-II), REDFT01 (DCT-III), REDFT11 (DCT-IV), RODFT00 (DST-I), RODFT10 (DST-II), RODFT01 (DST-III), RODFT11 (DST-IV), DHT (Hartley), R2HC and HC2R (halfcomplex). Their formulas are on Cosine, sine and Hartley transforms.

Passes

Batched one-dimensional transforms of strided arrays, the operations NFFT.jl builds on.

FFTL.plan_pass — Function
plan_pass(v::StridedArray{<:Complex}, d; sign = -1, threads = 1, nonzero = nothing, needed = nothing)

Plan for the batched 1D DFT along dimension d of arrays with the size and strides of v (sign = -1 forward, +1 unnormalised backward). Apply with mul!(w, p, v) (w with the same size and strides, w === v in place) or apply!(p, v). With threads > 1 the lines are split among threads, and a single long line (d = 1) uses the four-step algorithm; callers that thread over many arrays themselves keep the default 1.

nonzero (ranges of indices along d, e.g. (1:a, b:n)) declares that each line is zero outside these ranges; needed that only these outputs of each line are used (the others may hold anything afterwards). The first resp. last stage then skips the zero inputs resp. the unneeded outputs.

source
FFTL.plan_r2r_pass — Function
plan_r2r_pass(v::StridedArray{<:Real}, d, kind; threads = 1)

Plan for the real-to-real transform kind (REDFT00 … RODFT11, DHT, R2HC, HC2R; unnormalised) along dimension d of all lines of arrays with the size and strides of v. Apply in place with apply!(p, v) or into an array of the same layout with mul!(w, p, v).

source
FFTL.apply! — Function
apply!(p::PassPlan, v)

The transform of p applied to v in place.

source

GPU

Available after using KernelAbstractions and a GPU package.

FFTL.plan_ka — Function
plan_ka(backend, T, dims, σ; region = 1:length(dims), gmax = 64, radices = nothing)

DFT plan (σ = -1 forward, +1 unnormalised backward) for arrays of size dims with element type Complex{T} on a KernelAbstractions backend (Metal, CUDA, ROCm, oneAPI, CPU), along the dimensions region. Requires using KernelAbstractions; with a GPU package loaded, FFTL.plan_fft(x) etc. return these plans for GPU arrays. Apply with p * x or mul!(y, p, x) (y !== x); kernels are queued on the backend without synchronization.

source
FFTL.plan_ka_rfft — Function
plan_ka_rfft(backend, T, dims; region = 1:length(dims))
plan_ka_brfft(backend, T, dims; region = 1:length(dims))
plan_ka_r2r(backend, T, dims, kinds; region = 1:length(dims))

Real-input forward DFT (half spectrum along region[1]), its unnormalised inverse (dims is the size of the real array in both) and real-to-real transforms (one R2RKind per dimension) on a KernelAbstractions backend. Requires using KernelAbstractions; with a GPU package loaded, FFTL.plan_rfft, plan_brfft, plan_irfft and plan_r2r return these plans for GPU arrays.

source

plan_ka_brfft and plan_ka_r2r are documented with plan_ka_rfft.

Cache and configuration

FFTL.clear_cache! — Function
clear_cache!()

Drop the twiddle and filter tables that FFTL keeps for reuse by later plans.

source
FFTL.cpu_caches — Function
FFTL.cpu_caches()

Cache sizes the CPU plans are sized from: L1 data and L2 per core, last-level cache per core cluster, in bytes, and where they come from (:queried, :default, :user).

source
FFTL.set_cpu_caches! — Function
FFTL.set_cpu_caches!(; l1, l2, llc)

Override the cache sizes (bytes) that plans are sized from, e.g. when the query at load time fails or a machine reports misleading values. Affects plans made afterwards. FFTL.set_cpu_caches!() restores the queried values.

source
FFTL.PRECOMPILE_WORKLOAD — Constant
FFTL.PRECOMPILE_WORKLOAD

The precompile workload selected when FFTL was built: "lean" (default), "broad" or "none". It comes from the precompile_workload preference:

using Preferences, FFTL
Preferences.set_preferences!(FFTL, "precompile_workload" => "broad"; force = true)

The next load recompiles FFTL with the selected workload.

source

The plans of the generic and the GPU paths follow the same protocol; see AbstractFFTs.
