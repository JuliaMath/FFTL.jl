Compiling ahead of time

juliac --trim (Julia 1.12 and newer) compiles a Julia program into an executable or a library that contains only the code the program can reach. Every call must be resolvable when the program is compiled. The normal FFTL plans do not meet this: their type contains the radix sequence, which is computed from the size at run time, so constructing a plan builds a new type.

For trimmed programs, FFTL has plans whose radix sequences and sizes are data:

plantransformapplied with
FFTL.RPlan{T}(sz, region, σ)complex DFT, sign σmul!, *, \, or FFTL.execute! on pointers
FFTL.RRFFTPlan{T}(sz, region, σ)r2c (σ = -1) or unnormalised c2r (σ = +1)FFTL.execute_r2c!, FFTL.execute_c2r! on pointers
FFTL.RR2RPlan{T}(sz, kinds, region)real-to-real, one kind per dimensionFFTL.execute_r2r! on pointers

T is Float32 or Float64; sizes, regions and kinds are vectors. All three take the threads keyword. They compute the same transforms with the same strategies as the normal plans (Bluestein, four-step, fused planes); per stage they dispatch at run time, which costs a little speed. libfftl is built from exactly these plans, so they are the tested route through juliac --trim=safe.

using FFTL, LinearAlgebra

x = randn(ComplexF64, 48, 30)
p = FFTL.RPlan{Float64}([48, 30], [1, 2], -1)
y = similar(x)
mul!(y, p, x)
y ≈ fft(x)
true
r = randn(16)
q = FFTL.RR2RPlan{Float64}([16], [FFTL.REDFT10], [1])
out = similar(r)
GC.@preserve r out FFTL.execute_r2r!(q, pointer(out), pointer(r))
out ≈ FFTL.r2r(r, FFTL.REDFT10)
true

The pointer functions expect column-major arrays of the plan's size, which the caller keeps alive (GC.@preserve). The source of libfftl (libfftl/src/libfftl.jl) shows the rules the calling code follows to stay trimmable: no closures that capture types, concrete element types at every call, error messages as literal strings.
