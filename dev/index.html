FFTL.jl

Fastest Fourier Transform in Lübeck: a Fourier transform library in pure Julia. Complex, real and real-to-real transforms of Float32 and Float64 arrays, any number of dimensions, any length, several threads, SIMD on the CPU, KernelAbstractions on GPUs, and a C library (libfftl) compiled from the same code.

Experimental

FFTL.jl is under development and not registered yet. The interface can still change; the documented parts are the ones tested in CI.

What you get

  • Every transform you use. Complex, real-input and all eleven real-to-real kinds (DCT-I to DCT-IV, DST-I to DST-IV, Hartley, halfcomplex), along any set of dimensions of any rank.
  • Any length. Smooth lengths go through codelets; lengths with large prime factors go through Bluestein's algorithm. No padding to powers of two.
  • Plans that behave like the rest of the ecosystem. Every plan is an AbstractFFTs.Plan: mul!, *, inv, \. See Using FFTL next to FFTW.jl.
  • Parallel where it pays. Threads are used only when the transform is large enough, and a single long line uses the four-step algorithm. See Threads.
  • Numbers in their own precision. BigFloat and other floating-point types are transformed in that type, not converted to Float64.
  • A C library without a Julia installation. libfftl is FFTL trimmed with juliac, with the same transforms in single and double precision.

Quick start

using FFTL, LinearAlgebra

x = randn(ComplexF64, 1000, 1000)
y = FFTL.fft(x)                  # all dimensions, unnormalised
x2 = FFTL.ifft(y)                # normalised inverse
x2 ≈ x
true
p = FFTL.plan_fft(x)             # a plan holds the work buffers and tables
mul!(y, p, x)                    # apply it, as often as you like
y ≈ FFTL.fft(x)
true
r = randn(1000, 1000)
R = FFTL.rfft(r)                 # half spectrum along dimension 1: 501 × 1000
FFTL.irfft(R, 1000) ≈ r
true
C = FFTL.dct(r)                  # orthonormal DCT-II; idct inverts it
FFTL.idct(C) ≈ r
true

Design in one paragraph

A plan is a Julia object that carries the radix sequence, the twiddle tables and the work buffers for one size and one set of dimensions. Radix sequences are chosen by a fixed rule, and the codelets they run are generated for the radix, element type and SIMD width actually used. Long transforms run on several threads, and lengths with large prime factors go through Bluestein's algorithm. The details are in Explanation.
